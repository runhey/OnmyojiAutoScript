# 项目规则

## 目录结构

如果是 worker 独有的放到 `script/`，否则放到 `oas/`，且必须按照领域来划分。

## 代码风格

1. **不写 `__all__`**。模块的公开接口由命名和文档表达，不维护 `__all__` 清单。
2. **优先用类承载行为**，不要把所有操作都写成散落的模块级函数。无状态的用
   `@staticmethod` / `@classmethod`，有状态的用实例方法。能放进一个类的方法，
   不要再单独开一个模块或一堆自由函数。
3. **接口数量尽量少**。每个阶段只保留一个入口，不要为每个内部步骤都暴露一个
   公开函数；公开 API 越少越好。

## 工作流程

4. **写代码前先列清单**：先给出要新增/修改的类、方法、函数，以及它们各自负责
   什么，数量尽量少；经用户确认后再正式写代码。不要未经确认直接堆实现。
