# 悬赏封印新版界面适配（2026-10-30）

## 变更
- 更新主界面一键追踪/取消追踪、单任务追踪状态和详情关闭标志。
- 新增“前往探索”入口。普通模式、只做协作模式均不再通过庭院绕行；跳转后检查探索页标志。
- 更新四张任务卡的协作邀请入口，支持非连续位置的协作任务；奖励类型模板复用，重新限定搜索区域。
- 随机邀请和指定好友邀请统一提交悬赏专用“邀请”按钮，必须点击过按钮并确认弹窗关闭、回到主界面才算提交完成。
- 单任务详情关闭使用右上角关闭按钮，不再使用旧版空白位置。
- 更新四行来源按钮和 OCR 区域，兼容“式神碎片”宽标签，章节 OCR 按来源类型排除标签。
- 收到协作邀请属于全局中断：更新接受、拒绝、忽略和猫粮模板，调整勾玉/狗粮奖励搜索区域；不改变用户接受策略。

## 生成与测试
素材 JSON 是源，assets.py 由 dev_tools.assets_extract.AssetsExtractor 按目录生成。
只生成 tasks/WantedQuests 和 tasks/GlobalGame，避免影响其他任务。

在项目根目录执行：
```
.\toolkit\python.exe -m unittest discover -s tests/tasks/WantedQuests -v
```
测试不初始化 Device，不连接游戏，不发送邀请。

## 验证边界
- 用户九张截图按 1280×720 归一化，55 项图片匹配正/负例通过。
- 15 项流程单元测试通过，包括邀请必须提交、提交后必须关闭弹窗、两种模式直达探索、第四张卡协作和来源解析。
- 使用实际 OCR 离线识别来源，分别验证“探索优先”和“挑战优先”选择正确行；战斗函数替换为 Mock，未消耗游戏资源。
- 原有庭院主题 4 项、结界皮肤 5 项测试通过。
- 保留未提供截图的现世任务标志、跨区高亮及战斗场景素材。狗粮接收奖励仅移动搜索区，尚无新版正例截图。
- 当前只完成离线验证，不把截图测试等同于游戏端完整运行。实际窗口检查时存在用户输入及远程工具遮挡，未向游戏发送测试点击。
- 来源面板目前仍按前四行处理；未新增妖气/年兽战斗支持，也未新增来源列表滚动策略。

## 使用
停止正在运行的任务，重启 OSA 后端以重新载入 Python 模块和素材缓存，再单独运行悬赏封印。
这不是选项或翻译变更，不需要更新翻译。
游戏界面要保持无遮挡，且不要同时手动操作或运行第二个控制同一游戏窗口的脚本。
备份在本次 Codex 会话 outputs 中。此次未改用户任务配置，未提交 GitHub。
